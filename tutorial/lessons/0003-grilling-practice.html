Lesson 0003 · 约 12 分钟

grilling 实操演练：坐上被拷问者的位置

前置：0002 主线工作流走查 ｜ 配套阅读：05 · grilling 节 · 速查表 ｜ 下一课：深模块词汇专题

本课的目标（一个 Win） 你将在这页里亲身经历一场被压缩的 grilling：一个模糊想法 → 两轮提问 → 领域词汇与 ADR 落地。 完成后你第一次跑 /grill-me 时不会陌生，而且知道怎么当一名好受访者。

1. 开场：你的模糊想法

设定：你用 Astro + GitHub Pages 维护一个技术博客，读者越来越多， 你想——“给博客加个评论系统吧”。就这一句。没有别的要求。

在真实场景里，你现在会在一个全新对话里敲 /grill-me（没有仓库压力时）， agent 立刻开始把你这句话拆成一棵设计树，并计算第一轮的 frontier： 前置已明确、现在就能问的问题。下面开始。每题选一个选项（➡️ 推荐 的含义是： 选它等于"yes，同意推荐"）。

2. 复盘：刚才发生了什么

  • Frontier 在动：第二轮的问题是你第一轮的答案解锁的——你选了不同的登录策略，就会被问不同的后续问题。这就是"每轮答案重塑设计树"。
  • 事实没来烦你："博客用什么框架"这种问题 agent 自己派子代理去查了。你的时间只花在决策上。
  • 词汇当场结晶：会话中的关键概念当场写进 GLOSSARY——下次你说"评论者"，agent 不用再问是什么。
  • 决策过了三道门才进 ADR：不是所有决定都配 ADR；够不上门槛的只留在对话和 spec 里。
最重要的提醒：Passivity（被动）是失败模式 在这场模拟里，每一题你都可以选非推荐项——那不是"答错"，那正是你做决定的时刻。 真实会话的验收标准（docs 原文）："You disagree with something. A session with no pushback from you is a session you didn't need."（一路 "agreed, agreed" 的会话，是你不需要的会话。）

3. 现在去跑真实版

  1. 开一个全新对话（不要在已有方案的对话上叠加；关掉 plan mode，否则 agent 急着出计划不肯问）。
  2. 没有仓库压力的想法（写作、决策、人生）敲 /grill-me；在自己项目里敲 /grill-with-docs。
  3. 自检三件事：① 每轮你是否至少 pushback 过一次？② 它有没有问你"你能自己查到的事实"？（有的话指出来）③ 结束时它是否停下来等你确认共识，而不是直接开写？
  4. 卡在"跑起来才知道"的问题上？让它转 /prototype；卡在"只有某个人知道"的问题上？用 /to-questionnaire。

4. 检验一下

1. grilling 里"查证事实"是谁的工作？

✅ "Finding facts is your job, never the user's."——agent 派子代理查环境事实，绝不拿你能自己查到的东西烦你；决策才归用户。

2. grilling 会话什么时候算结束？

✅ frontier 为空 = 没有沉默假设；但"Do not act on it until the user confirms"——确认门防止较弱的模型问两三个问题就跑去写 outline。（刻意没有问题数上限。）

3. 为什么每个问题都附推荐答案？

✅ 措辞让"yes"即接受推荐——把开放式盘问变成快速审批 + 纠偏，你可以按编号整轮作答（"1 yes, 2 选第二个, 3 no"）。

4. 哪种问题应该转去 /prototype 而不是硬聊？

✅ "ungrillable"问题（状态机对不对？UI 该长啥样？）靠谈无法回答，硬谈会越拖越长——转 prototype 做可抛弃原型。别人的脑袋 → to-questionnaire；外部文档 → research。

5. 收尾

推荐的首要资料 grilling 的 SKILL.md 原文 ——只有 30 行，是全仓库被复用最多的原语。读一遍你会认出本课模拟里的每个机制：rounds、frontier、推荐答案、事实/决策分工、确认门。
有任何不清楚的？直接问你的 agent 比如："和我用中文 grilling 一次，主题随便你挑"、"grill-with-docs 会往 GLOSSARY 写什么？ 给我看真实例子"、"如果我不喜欢一轮多问，怎么办？"（答案：往 CLAUDE.md 加一行 "When grilling, ask one question at a time"——docs 说这是 supported setting，不是 workaround。）
