调用类型与失败模式：读懂这个仓库的钥匙

本课的目标（一个 Win） 学完这课，你打开仓库 README 时能立刻看懂它为什么把 skill 分成两组， 并且能对任何一个 skill 说出：它是谁在什么时机触发的、它对应哪个失败模式。

1. 先记住四种痛

作者在 README 里说， 这 38 个 skill 全都为了对抗 agent 编码的四种真实失败（详见 01 全景图）：

#失败模式一句话解药
①没做我想要的（对齐失败）动手前让 agent 反过来拷问你（grilling 家族）
②太啰嗦（语言不共享）维护 GLOSSARY.md 共享语言（domain-modeling）
③代码跑不起来（反馈缺失）红绿循环 + 诊断循环（tdd、diagnosing-bugs）
④造出大泥球（设计腐化）深模块词汇 + 深化普查（codebase-design 等）

2. 唯一的分类轴：谁能触发它

仓库不按"功能"分类，只按调用权限分两类（定义见 .agents/invocation.md）：

user-invokedmodel-invoked
谁能触发只有你，手动敲命令agent 自主判断触发，你也可以手动
角色编排者（orchestrator）纪律承载者（reusable discipline）
例子grill-with-docs、implementgrilling、tdd、code-review

一条不变式贯穿全仓库：

user-invoked 可以调用 model-invoked，但绝不调用另一个 user-invoked。 所以主链条（grill → spec → tickets → implement → review → retro）每一环都由你驱动。

为什么这样分？

  • 防乱触发：user-invoked 被两个开关双重排除在模型可达范围外——"agent 永远不会自己发起对你的访谈"，这是硬保证。
  • 纪律复用：grilling 这一份访谈纪律，被 grill-me、grill-with-docs、triage、wayfinder、improve-codebase-architecture 五个入口复用——改一次，全体受益。
  • 人是所有者：入口由人掌控，"怎么做才对"交给 agent——查证是 agent 的事，拍板是你的事。

3. 检验一下

四道题，每题点一个答案，立即反馈。（答错也没关系， explanations 里都有出处。）

1. 哪个说法准确描述了 user-invoked skill？

✅ user-invoked 只能由人手动触发（"user-invoked 的 description 是写给人类看的一行摘要"）。用户和模型都能触发的是 model-invoked。

2. grilling 里的 "frontier" 指什么？

✅ frontier = 前置决策已全部敲定、"现在就能问、不用猜还没听到的答案"的问题集合。一轮问完整个 frontier，frontier 为空才算结束。

3. 哪条规则约束 skill 之间的调用？

✅ user-invoked 可通过 Skill tool 调用 model-invoked（如 implement 调 tdd），但绝不调另一个 user-invoked。链条由用户驱动。

4. "大泥球"（设计腐化）的主要解药是哪组？

✅ 失败模式④的解药是 improve-codebase-architecture（深化普查）+ codebase-design（深模块词汇），以及把设计意识前置的 to-spec / to-tickets。访谈对应①，红绿循环对应③。

4. 收尾

推荐的首要资料 README 的 "Why These Skills Exist" 四节 ——作者亲口讲四种失败模式和它们的解药，5 分钟读完，是理解整个仓库的钥匙。
有任何不清楚的？直接问你的 agent 它是你的老师。可以问它："带我看看 grilling 的 SKILL.md 原文"、 "为什么 grill-me 只有一行？"、"用 implement-spec 和逐张 implement 各适合什么场景？"—— 或者让它带你走一遍 07 工作流组合 的完整旅程。
